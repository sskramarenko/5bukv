# Решатель «Пяти букв» — телеграм-бот

Подсказывает оптимальные ходы в русском Wordle. Сразу советует первое слово,
после каждого отклика пересчитывает живых кандидатов и предлагает лучший ход.

## Что нужно залить в репозиторий

```
bot.py
dict_bot.txt          ← словарь, обязателен (сейчас 3530 слов)
requirements.txt
```

Без `dict_bot.txt` бот не запустится и напишет об этом в лог.

## Переменные окружения на Bothost

| переменная | обязательна | что делает |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `ADMIN_IDS` | да | ваш id через запятую: админ без ограничений, ему же уходит копия памяти |
| `ALLOWED_CHATS` | нет | id чатов, где бот работает. **Пусто — работает везде** |
| `PAYWALL` | нет | `1` — включить лимит бесплатных слов. По умолчанию выключено |
| `FREE_WORDS` | нет | сколько слов бесплатно, по умолчанию 3 |
| `PAY_TEXT` | нет | свой текст с реквизитами, который бот покажет при исчерпании лимита |
| `UNLOCK_CODES` | нет | заранее заданные коды через запятую (можно не задавать — см. `/codes`) |
| `STORAGE_CHAT` | нет | куда складывать копию памяти; по умолчанию первый из `ADMIN_IDS` |

Свой id узнать: добавить бота и написать `/myid`.

## Два режима

**Сейчас — только для своих.** Задайте `ALLOWED_CHATS` = id группы, `PAYWALL`
не задавайте. Бот отвечает только в этой группе, без ограничений.

**Потом, если продавать.** Уберите `ALLOWED_CHATS` (бот станет доступен всем),
поставьте `PAYWALL=1`. Три слова каждому бесплатно, дальше просит код.

## Как работает оплата

1. Человек израсходовал бесплатные слова — бот показывает текст из `PAY_TEXT`.
2. Он платит так, как вы написали в этом тексте (перевод по номеру телефона,
   СБП, ссылка — что угодно, бот в это не вмешивается).
3. Вы генерируете коды командой `/codes 5` — бот пришлёт пять штук вида
   `K7FM-39QX` и запомнит их.
4. Человек вводит `/code K7FM-39QX` — доступ открыт навсегда,
   код погашен и второй раз не сработает.

Команды для вас: `/codes N` — новые коды, `/grant <id>` — открыть доступ
вручную, `/revoke <id>` — закрыть, `/stat` — кто сколько слов разобрал
и сколько кодов осталось.

## Память не теряется при деплое

Bothost стирает диск при каждой пересборке, поэтому бот раз в две минуты
отправляет файл `solver_data.json` в личку первому админу и закрепляет его
там. После пересборки поднимает данные из этого закреплённого сообщения —
оплатившие пользователи и погашенные коды не пропадают.

**Важно:** не открепляйте это сообщение в переписке с ботом.

## Соседство с игровым ботом

В группе оушена рядом работает игровой бот, и команды у них раньше совпадали —
на `/new` отвечали оба. Поэтому у решателя свои имена команд:

| решатель | что делает | почему не как обычно |
|---|---|---|
| `/solve` | новое слово, сброс | `/new` занят игровым ботом |
| `/hint` | подсказать ход сейчас | — |
| `/rules` | справка | `/help` занят |
| `/myid` | id чата и свой id | `/chatid` занят |
| `/sinfo` | версия сборки | `/version` занят |

`/state`, `/list`, `/undo`, `/pay`, `/code` не пересекаются и оставлены как были.

Второе: **в группе решатель отвечает только на точный формат** — слово и ровно
пять цифр из 0/1/2. На одиночное слово («Ролик» — это ход в игровом боте), на
опечатки в откликах и на обычную болтовню с числами он молчит. В личке всё
по-прежнему: подсказывает, что не так с форматом.

Формат ввода: слово и пять цифр, `0` — буквы нет, `1` — есть не здесь,
`2` — на месте. Можно слитно (`норка00022`), можно несколько ходов сразу
с новой строки или через `;`. Ё приводится к Е автоматически.

## Чем отличается от задания

В ТЗ предлагалось считать матрицу откликов 5060×5060 (26 МБ) и кэшировать
её в `fb_cache.npy`. Я сделал иначе: матрица считается на лету только против
живых кандидатов. Причины:

- первый ход всё равно зафиксирован («норка»), а дальше живых кандидатов
  уже сотни, не тысячи — считать всё целиком незачем;
- Bothost стирает диск при деплое, так что кэш пересчитывался бы каждый раз
  по 17 секунд;
- отклик на ход занимает 0,1 секунды при 18 кандидатах и около секунды
  в худшем случае (если первым ходом всё уйдёт в молоко).

Важное следствие: **размер словаря нигде в коде не зашит.** Заменить словарь —
значит просто положить в репозиторий новый `dict_bot.txt` и перезапустить бота.

Расчёт вынесен в отдельный поток, поэтому бот не подвисает для остальных,
а при большом числе кандидатов сначала пишет «считаю…».

Второе отличие — фильтр мусора. Правило из ТЗ (отбрасывать Zipf < 2,0, если
есть альтернатива не хуже 15 %) оставлено, но добавлен слой перед ним: слова
с нулевой частотой в советах не предлагаются совсем. Игра их чаще всего
не примет, и ход уйдёт впустую. В списке живых кандидатов они по-прежнему
видны. В словаре версии 2 таких слов 411 — меньше, чем было, но слой
по-прежнему нужен.

## Проверено

На словаре версии 2 (3530 слов):

- векторный расчёт отклика сверен с эталонной функцией из ТЗ на 62 500 парах,
  расхождений нет (включая повторные буквы);
- 50 партий на случайных обиходных словах: решены все, в среднем 3,3 попытки,
  медиана 3, худший случай — 6 («пайка»: норка → латыш → спазм → папка →
  пачка → пайка, семейство папка/пачка/байка/пайка различается одной буквой);
- расчёт с нуля подтверждает первый ход: «норка» даёт ожидаемый остаток
  144,5 слова и выходит **первой из 3530** (на прежнем словаре была второй).
